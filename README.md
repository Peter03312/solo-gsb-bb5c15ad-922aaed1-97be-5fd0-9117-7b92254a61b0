# 排练字幕修订台（Rehearsal Subtitle Reviser）

一款**本地运行**的排练字幕修订 Web 应用：导入 SRT 稿件后，从同一份原稿建立两条修订分支，
分别修正文案、起止时间、拆分 / 合并片段；合并时按**来源片段**识别双方改动，冲突片段
并排展示由用户选择，未冲突改动自动保留。全程基于 Node.js + SQLite + 浏览器前端。

## 功能一览

| 环节 | 说明 |
| --- | --- |
| 导入 | 粘贴或选择 `.srt` 文件；序号须从 1 连续、时间码格式严格、起点早于终点、片段不重叠、文本非空。**任何格式 / 时间码错误都会指出物理行号并整份拒绝**，不写入任何数据。 |
| 原稿 | 原始 SRT 全文只读保存，可随时查看；也是两条分支与合并的共同基线。 |
| 双分支 | 同一原稿一键创建 **A / B 两条独立修订分支**，互不影响。 |
| 修订 | 逐条修改文案与起点 / 终点时间；按时间中点**拆分**片段（拆完可再分别编辑）；相邻片段**合并**。 |
| 合并 | 三向合并（以原稿为基线，按片段携带的来源 id 识别）：仅一边改动自动保留；**两边触及同一来源片段则并排展示各自内容，必须由用户选择 A 或 B，不会按保存先后覆盖**。 |
| 导出 | 导出前检查时间非负、起点早于终点、片段不重叠、文本非空；**失败时列出所有问题片段且不生成文件**；通过后导出序号从 1 连续的标准 SRT。 |
| 恢复原稿 | 任一分支可一键恢复为原稿内容（放弃该分支当前修订）。 |

> 合并时即使片段被拆分或合并，也能正确识别来源：拆出的片段共享同一来源 id，
> 合并出的片段携带来源 id 的并集。

## 一键启动（Docker Compose，推荐）

前置条件：已安装 Docker 与 Docker Compose 插件。

```bash
docker compose up -d --build
```

启动后访问：

- **地址：** <http://localhost:3000>
- 端口可通过环境变量 `HOST_PORT` 修改，例如改用 8080：

  ```bash
  HOST_PORT=8080 docker compose up -d --build
  ```

停止：

```bash
docker compose down
```

SQLite 数据库保存在命名卷 `subtitle-data`（容器内 `/app/data/app.db`），重建容器数据不丢。

## 本地 Node.js 直接运行

前置条件：Node.js ≥ 20（含 npm）。

```bash
npm install
npm run init-db     # 初始化 SQLite 数据库与表结构（幂等，可重复执行）
npm start
```

访问 <http://localhost:3000> 。

## 配置

配置均通过环境变量提供，均为可选项：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；仅本机访问可设为 `127.0.0.1` |
| `DATA_DIR` | `./data` | 数据目录，SQLite 文件 `app.db` 位于其中 |
| `DB_PATH` | `$DATA_DIR/app.db` | 可直接指定 SQLite 文件完整路径 |
| `HOST_PORT` | `3000` | **仅 docker compose 使用**：宿主机映射端口 |

Docker Compose 下数据库位于容器 `/app/data/app.db`，已挂载到持久化卷。

## 使用流程

1. 首页导入 SRT（文件或粘贴）。若稿件有问题，错误框会列出每条错误的物理行号，修正后重新导入。
2. 打开稿件，在「修订分支 A」「修订分支 B」中分别点击 *从原稿创建分支*。
3. 在各分支中：点 **✏️ 修正** 改文案 / 起止时间，**✂️ 拆分**、**⑃ 与下一条合并**；改坏了可点 *恢复为原稿*。
4. 打开「合并 A+B」→ *计算合并预览*：
   - 无冲突组自动处理（采用单边改动 / 保留原稿），可折叠查看明细；
   - 冲突组展示原稿、A 版本、B 版本，点击选择采用哪一边；
   - 全部冲突选择后 *提交合并结果*。
5. 在「合并结果」或各分支页点 *导出 SRT*；校验不过会弹窗逐条列出问题片段，不会产生下载文件。
6. 「原稿」页可随时 *查看原始 SRT 全文*。

## SRT 格式要求

- 序号必须是 **从 1 开始、逐块 +1 的连续整数**；
- 时间码严格形如 `00:00:01,000 --> 00:00:03,500`（小时:分钟:秒,毫秒，逗号分隔）；
- 分、秒不超过 59，起点严格早于终点；
- 相邻片段时间区间不重叠（首尾相等允许）；
- 每块至少一行非空文本；
- 文件以 UTF-8 编码（允许带 BOM）。
